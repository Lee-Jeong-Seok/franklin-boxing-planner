1

연계 개요 및 핵심 목표 (Why Connect?)

두 시스템은 각자의 영역에서 탁월한 강점을 보유하고 있습니다. 주간 업무 보고 시스템은 조직 차원의 업무 배분과 주간 진척도 관리에 특화되어 있으며, 프랭클린 타임박싱 플래너는 개인의 하루 30분 단위 초집중 실행과 로컬 암호화 보안에 특화되어 있습니다.

🏢 주간 업무 보고 시스템 (Macro)
조직 / 협업
  • 단위: 주간(Week), 부서/팀, 프로젝트
  • 핵심 가치: 목표 수립, 진척도 보고, 승인 및 권한 관리
  • 데이터 저장: 사내 중앙 DB (PostgreSQL)
  • 핵심 화면: 그리드, 칸반, 간트, 달력, 실적 모달
⌛ 프랭클린 타임박싱 플래너 (Micro)
개인 / 실행
  • 단위: 일일(Day), 30분 단위 타임박스 격자
  • 핵심 가치: A/B/C 우선순위 실행, Plan vs Exec 비교, 일일 회고
  • 데이터 저장: 클라이언트 로컬 영구 암호화 (AES-GCM)
  • 핵심 화면: 2열 타임박스 그리드, 비전 보드, 일일 피드백
💡
연계로 얻게 되는 핵심 사용자 경험 (UX): 월요일 아침, 주간 업무 보고의 내 Task를 프랭클린 플래너로 1초 만에 가져와 오늘의 A/B/C 우선순위로 배치하고, 매일 30분 단위로 몰입 실행합니다. 금요일 오후에는 플래너에 누적된 5일치 수행 기록과 투입 시간이 주간 실적(Weekly Summary) 보고서로 원클릭 자동 완성됩니다.

3대 연계 방식 비교 분석 및 최종안 선정

[1안] 느슨한 결합형 API 연동 (독립 웹앱 유지 + 개인 연동 키)

두 프로그램을 완전히 분리된 별개의 웹앱으로 유지하면서, 사용자가 발급받은 개인 API Key를 플래너에 등록하여 필요할 때만 API로 데이터를 주고받는 방식입니다.

✔️ 장점
  • 두 레포지토리의 소스코드 구조 및 배포 환경이 100% 독립 유지됨
  • 프랭클린 플래너의 기존 비즈니스 모델(Free/Essential)에 영향 없음
❌ 단점
  • 사용자가 두 개의 웹페이지 탭을 번갈아가며 전환해야 함
  • API 토큰 발급 및 등록 과정이 번거로울 수 있음

[2안] 주간 업무 보고 시스템 내 인앱(In-App) 타임박스 뷰 통합

주간 업무 보고 시스템 상단 툴바(그리드, 칸반, 간트 등)에 `[타임박싱]` 탭을 신설하고 Flutter Web으로 플래너 UI를 새로 개발하여 시스템 내부에 완전히 내장시키는 방식입니다.

✔️ 장점
  • 화면 이동 없는 극상의 All-in-One 일관된 사용자 경험
  • Task 상태 및 진척도가 타임박스와 실시간 완벽 동기화
❌ 단점 및 전환 사유
  • 2열 30분 타임박스 리사이징/드래그 위젯을 Flutter로 재구축해야 하므로 개발 공수가 큼
  • 개인 플래너 독립 배포판과의 코드 중복 및 개인정보 격리 로직 복잡화

[3안] 하이브리드 브릿지 통합 (★ 최종 권장안 채택)

BEST HARMONY

독립된 고성능 프랭클린 웹앱의 정체성을 보존하면서, 주간 업무 보고 시스템의 **사이드바 퀵 런처 + 브라우저 SSO 세션 브릿지 + 양방향 원클릭 데이터 파이프라인**을 통해 인앱 수준의 매끄러운 사용성을 제공합니다.

기능 영역 작동 메커니즘 보안 및 데이터 특성
🚀 단일 진입점 주간보고 사이드바 내 바로가기 메뉴로 플래너 팝업/새창 호출 SSO 세션 토큰 자동 연동 (추가 로그인 불필요)
📥 주간업무 가져오기 플래너 상단 [주간 업무 가져오기] 버튼 클릭 시 내 Task 팝업 표출 사내 API GET /api/tasks/my 실시간 안전 통신
📤 주간실적 자동취합 주간보고 실적 모달 내 [플래너 5일 기록 취합] 클릭 시 요약문 자동 완성 브라우저 로컬 스토리지 브릿지로 0.1초 만에 파싱 주입
3

양방향 데이터 흐름 및 아키텍처 다이어그램

📊 주간 업무 보고 ⇄ 프랭클린 플래너 상호 데이터 파이프라인
🏢 주간 업무 보고 시스템
  • TaskMaster (담당자, 상태, 우선순위, 마감일)
  • WeeklyRecord (금주 요약, 차주 계획, 이슈)
  • PostgreSQL DB (중앙 서버 저장)
➡️ ① 업무 가져오기 (Import)
GET /api/tasks/my
⬅️ ② 실적 자동취합 (Export)
Task 완료 & 투입시간 요약
⌛ 프랭클린 타임박싱 플래너
  • Tasks (A/B/C) (1일 단위 우선순위 목록)
  • Timeboxes (30분) (계획 Plan vs 수행 Exec)
  • AES-GCM 암호화 (브라우저 IndexedDB)
🔄 데이터 필드 매핑 테이블 (Data Field Mapping)
Schema Contract
주간 업무 보고 필드 매핑 방향 프랭클린 플래너 필드 변환 및 비즈니스 규칙
TaskMaster.id ➡️ Import task.weeklyTaskId 플래너 Task 객체에 옵셔널 ID로 보존 (추적용)
Task.dynamicData['제목'] ➡️ Import task.text 일일 할 일 명칭으로 자동 주입
Task.dynamicData['우선순위'] ➡️ Import task.priority (A/B/C) '상'->A, '중'->B, '하'->C 자동 변환
WeeklyRecord.summary ⬅️ Export 5일간 완료 Task (status='V') 주간 완료 목록 및 총 투입 시간(Hours) 마크다운 자동 생성
WeeklyRecord.issue ⬅️ Export 5일간 연기 Task (status='→') 연기된 사유 및 지연 업무를 이슈 란에 자동 제안
4

보안 및 개인정보 격리 원칙 (Security & Privacy)

프랭클린 플래너의 철학인 개인정보 보호 최우선(Privacy-First)과 주간 업무 보고 시스템의 기업 보안 규정을 모두 만족시키기 위해 명확한 격리 원칙을 수립합니다.

🔒 100% 로컬 영구 암호화 (서버 미전송)
  • 사명 선언문 (Mission Statement): 인생의 궁극적 목표
  • 핵심 가치 (Core Values): 개인의 의사결정 기준
  • 장기 목표 (Long-term Goals): 5년/1년 단위 개인 목표
  • 일일 피드백 및 개인 일기: 사적인 반성과 감정 기록
  • ※ 사용자 PIN 기반 PBKDF2 + AES-GCM 256bit로 클라이언트 암호화
🌐 안전한 사내 API 연동 영역 (공무 데이터)
  • 사내 할당 업무 (TaskMaster): 제목, 담당자, 마감일자
  • 주간 업무 실적 요약 (Weekly Summary): 업무용 완료 내역
  • 타임박스 투입 시간 통계: 주간 총 소요 시간(Hours)
  • ※ 하이웍스 SSO 인증 토큰 및 HTTPS(SSL) 암호화 통신 적용
5

단계별 개발 및 배포 로드맵

1
Phase 1: 통합 아키텍처 및 API 인프라 구축 (Server)
• 주간 업무 보고 서버에 GET /api/tasks/my (내 미완료 업무 전용 조회) 엔드포인트 신설.
• 외부 클라이언트 연동을 위한 API 연동 토큰/키 발급 및 인가 미들웨어 탑재.
2
Phase 2: 프랭클린 플래너 '주간 업무 가져오기' 개발 (Frontend)
• public/index.html 상단 툴바에 [주간 업무 가져오기] 버튼 및 사내 업무 선택 모달 탑재.
• 업무 선택 시 원클릭으로 A/B/C 우선순위 할 일로 등록 및 30분 타임박스 드래그 연동.
3
Phase 3: 주간 실적 모달 '플래너 주간 기록 원클릭 취합' 개발
• 주간 업무 보고 task_detail_modal.dart 내에 [플래너 주간 기록 취합] 버튼 신설.
• 이번 주 5일치 완료 Task와 투입 시간 통계를 파싱하여 마크다운 양식으로 금주 요약(Summary)에 자동 주입.
4
Phase 4: 사이드바 퀵 런처 단일 진입점 & 매뉴얼 갱신
• 주간 업무 보고 좌측 사이드바에 [프랭클린 타임박싱 플래너] 퀵 런처 메뉴 연동.
• 사용자 매뉴얼(User_Manual.html) 갱신 및 최종 통합 테스트 수행.
